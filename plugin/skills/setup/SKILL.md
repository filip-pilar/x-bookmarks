---
name: setup
description: Set up Bookmark Library on an Apple silicon Mac, connect X, and open its minimal import controls.
---
Run `python3 scripts/setup.py` from this plugin root when `x-client.json` is bundled or the library is already configured. Otherwise supply the owner's X app public Client ID with `--client-id`. Setup provisions missing Homebrew dependencies when Homebrew is installed, a private Python 3.14 environment, the pinned Gemma checkpoint, and bundled native helpers. Default data directory: `~/Library/Application Support/BookmarkLibrary`. The script downloads models and dependencies but never fetches bookmarks. If Google requests model-license consent, let the user accept the model terms and authenticate locally; do not request their token in chat. Preserve an existing configured library and token. If its Client ID differs from a bundled shared app, explain the difference and ask before changing the connection.

Shared-app packages include the app owner's public Client ID in `x-client.json`; use it when the user intends to use that app and billing. For an own-app setup, create/configure the user's X native app when authorized, read its public OAuth 2.0 Client ID using available tools, and pass it explicitly with `--client-id`. Do not silently use a bundled or previously configured app when the user requested their own. Each user has separate Keychain tokens and local files. No API secret is required. X API costs accrue to the developer account that owns the app. The app uses callback `http://127.0.0.1:8765/oauth/x/callback`, read access and scopes `tweet.read users.read bookmark.read offline.access`. If changing the app on an existing connection, disconnect first and reconnect after setup.

Complete authorized setup actions using available tools without asking for permission again. Reuse matching sign-ins and approvals, make routine choices, and continue independent work while awaiting required input. Call `open_library` after setup and plugin installation to open the controls beside the conversation where supported. Start Connect X through available permitted controls and continue the authorized browser flow. Ask the user for a click, login, account-access confirmation or Keychain action only when the interface or platform requires their personal interaction, or the necessary authorization is missing. Do not bypass app/OS approval controls. Then check `status` and confirm the intended app/account and paused state. Do not start imports, source fetching or schedules during onboarding. If tools are unavailable, resolve supported refresh/re-enable steps; request only the specific desktop action or new local task actually required. Report a real blocker and the smallest next action instead of handing routine work back to the user.

For a custom data directory, setup supports `--library`. Set `BOOKMARK_LIBRARY_HOME` on the MCP server to that directory as well. One local library service can bind the registered callback port 8765 at a time.
