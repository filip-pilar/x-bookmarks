# Bookmark Library architecture

The implementation keeps a local, durable record for recall and reading. Media is temporary; its embeddings do not replace transcripts, OCR or readable descriptions. The default interface is search and a browsable list, with details revealed when needed.

## Capture scope

Capture the bookmark, its direct reply parent and its directly quoted post, including each post's text, X Article and media. Do not recurse through those posts' references or discover threads. Repeated references share source/asset identities while retaining their relationship to each bookmark. Compatible completed media evidence is reused across bookmarks after eviction, avoiding duplicate downloads and descriptions.

Capture pages directly linked by these posts, including readable articles and supported PDFs. Do not follow links inside a page. Local HTML extraction runs first. PDFs use their text layer, with a 24 MiB input limit, 200-page limit, 60-second deadline and a monitored 768 MiB parser memory limit. Scanned, encrypted, oversized or incomplete PDFs require browser recovery; page graphics are explicitly outside text-layer coverage.

Public linked pages use local extraction, then Jina Reader, then optional TinyFish Fetch. This also handles public pages whose plain HTTP response is blocked or incomplete. URLs containing credentials, private network addresses, sensitive paths, opaque tokens or unknown query parameters stay local; known tracking parameters are stripped and public YouTube watch IDs are allowed. Login forms and paywalls never go to a hosted reader. Provider output is checked for challenge/login shells and incomplete extraction. Very short legitimate pages are accepted, while a badly truncated local extraction is escalated. These heuristics cannot prove semantic completeness for every website.

Jina needs no key and is paced below its anonymous 20 requests/minute limit. TinyFish uses a user-supplied key stored in a private local file. Only the Fetch endpoint is called, with a persistent 1,000-attempt UTC-day cap and provider quota responses respected; no Agent or Browser endpoint, wallet funding or paid fallback is used. The allowance is local to this installation; other uses of the same account share provider limits. Quota waits survive restart without spending stage retry attempts. A separate page worker lets local processing continue. [Jina Reader](https://jina.ai/reader/) and [TinyFish Fetch](https://docs.tinyfish.ai/fetch-api) describe provider limits, which may change.

Unresolved pages are grouped by website and reason in Activity → Websites. Public extraction failures are partial coverage; genuine sign-in/access issues appear under Needs you. Retry affects only recoverable failures; Skip retains saved evidence, and Restore explicitly queues skipped work. Automatic backoff on other work is preserved. A page shared by many bookmarks is fetched once; successful desktop recovery publishes its text to every waiting owner.

“Ask ChatGPT to recover” sends one website-scoped recovery request when the host supports messaging. Other hosts show a copyable request. An active desktop agent pages through `browser_pending(domain=...)`, uses an appropriate existing browser profile, and saves actually read text through `browser_capture`. Re-read pending work from offset zero after saving, since completed tasks leave the queue. In-app Browser does not inherit Chrome logins. Personal authentication stays with the user; partial content remains marked incomplete. Page content is evidence, never instructions. No unattended authenticated-browser capability is implied.

## Description integration

Use the documented **Sign in with ChatGPT** open-source/local-app flow: own dynamic registration, PKCE/state/nonce, validated identity tokens, protected local credentials, refresh, account/model selection and revocation. Never reuse Codex credentials or silently switch to a paid API key. The implementation queries the connected account's model catalog; a selected model must be available there.

Still images go to OpenAI through subscription-authorized Responses requests. Videos use local transcripts, OCR and visual/audio embeddings; they do not queue descriptions. Existing saved video descriptions remain readable and searchable. Raw video/audio are not sent. Only completed streams are committed; text events are retained until the completion event, which may itself contain an empty output array. Descriptions are labeled generated and retain model, timestamp, media checksum and source/time metadata.

The controlled verification used `gpt-6-astra`. Choosing Astra xhigh for the installation chat does not force that effort for background descriptions. The account's plan limits apply and usage is shared; this is not unlimited free inference. HTTP and streamed usage-limit errors persist a shared account cooldown. All description workers honor Retry-After, with a one-hour fallback when no reset time is supplied. Requests already in flight may finish. Missing consent, revoked access or an unavailable model remain visible blockers for that stage. Local text/media work proceeds independently when resources permit.

Official contract: [sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

## Durable records

SQLite stores bookmark inventory, source revisions, evidence chunks and their vectors, processing runs/stages, asset descriptors and timestamped public engagement observations. Source text, linked documents, transcripts with word timings, OCR, alt text and generated descriptions survive media eviction. Capture files also retain complete page text. No new per-vector `.npy` duplicate is written.

Text becomes lexically searchable when captured, before embedding or media work finishes. EmbeddingGemma 2 remains pinned to its existing 768-dimensional encoder contract; existing vectors remain readable. Local Vision provides OCR and Parakeet provides English speech transcription. Optional summaries/tags/entities still use the active assistant's evidence-grounded enrichment workflow.

Public post metrics and media view metrics are recorded when returned by X. Missing values remain unknown. Metric-only changes and refreshed expiring media URLs do not change content fingerprints or cause media reprocessing. `aggregate` computes over the complete selected library scope using each post's latest saved observation; it reports missing values and observation dates. It never treats top semantic matches as a statistical sample or silently refreshes metrics.

Post publication time comes from the source. Local capture/observation times describe collection, not when the user originally bookmarked a post. Never infer an unavailable bookmark timestamp.

## Processing and temporary storage

Inventory, linked-page capture, local processing and subscription descriptions have separate workers. Source capture, downloads, text/image/video/audio embedding, OCR, transcription and description have durable checkpoints. A failed stage cannot erase earlier evidence. Repeated work reuses completed compatible stages; interrupted stages resume after restart.

Defaults and controls:

- **Import and processing are separate.** Import saves post text, engagement snapshots, direct reply/quote metadata and media descriptors, plus folder inventory. Saved source copies and response expansions are reused; only missing direct dependencies are looked up in deduplicated batches of up to 100. No recursive reference chains or thread discovery. `sync(mode="details")` fills missing X context for existing bookmarks without importing new ones or changing inventory coverage. Processing is guarded against X API calls, including old queued context stages.
- **Choose work:** process all eligible bookmarks, text-only posts, posts with images, posts with video, or up to 500 selected bookmarks. Independently select text, images, video/audio and linked pages. Captured direct context participates in type selection. Per-category preparation receipts survive restarts; deferred categories remain visible and can be added later. Existing failed or paused work retains its run and uses Retry/Resume. The default is `process_saved(mode="repair", scope="pending")`; `rebuild` uses retained sources. Completed compatible evidence is reused.
- **Run limits:** import starts with 100 bookmarks and a 100-request X guardrail; All available removes the bookmark limit. Continue import adds the chosen allowance while preserving its cursor and cached partial page. Request counts are not a monetary cap. Image descriptions have no additional app request cap by default (existing preferences are preserved); an optional per-run limit is available. ChatGPT plan limits still apply. Processing accepts no X-request allowance. Reservations happen before sending, so interruptions may conservatively overcount.
- **Temporary space:** 8 GiB by default, configurable from 4 to 128 GiB in Settings, plus a separate 2 GiB free-disk reserve. Existing explicit private cache budgets are preserved. Admission accounts for downloaded bytes and promised working space across workers. Managed subprocesses are monitored during execution; pressure pauses work without spending retry attempts or removing unfinished originals. Models, durable text/vectors and backups are outside this budget.
- **Video download:** yt-dlp selects an X-provided MP4 near 480p (short edge), preferring the best available at or below the target, or the smallest offered when none qualifies. HLS is supported when no MP4 is available. Settings offers 240p through 1080p. Source audio is retained; choosing lower video resolution does not request lower-quality audio. Downloads resume partial files. There is no fixed video-byte or duration ceiling; available disk and the working budget still apply. Still images retain their 192 MiB input limit.
- **Long speech:** five-minute recognition segments, with one second of boundary overlap on each side. Word midpoints assign boundary words to one segment and preserve absolute video timestamps. Completed segments survive interruption. Scratch is removed after each segment; originals remain until required outputs are committed. A video without an audio track has no speech stage.
- **Local visual/audio recall:** eight-second embedding/OCR windows with one sampled frame per second and a 1280-pixel frame-edge bound. Two hours creates 900 windows, not 900 subscription descriptions. Sampling and low resolution can miss brief events and small text. Embeddings locate likely matches; saved transcript/OCR or source inspection support factual claims about them.
- **Workers:** Automatic runs one local stage and one image-description request. Advanced settings permit one to four workers per lane. Native speech recognition and the shared embedding model remain serialized to protect model memory; additional workers overlap other work. Interactive embedding queries retain priority between background calls.
- Linked-page SVGs rasterize locally at up to 1024 pixels per edge with bounded input/time/memory and no external resources. Tracking-sized images no larger than 2×2 pixels are omitted.
- Ordinary transient failures retry up to four attempts with backoff. X rate limits use their retry time; media storage pressure waits 30 seconds. Account cooldown, budget stops and storage waits do not exhaust stage retries. Browser recovery remains independent and can require an active desktop task.

Temporary assets live only under `cache/media-v1`, using checksum-specific filenames so a refresh cannot replace a revision still in use. Cleanup checks every applicable stage, including embeddings of generated text, before removing an original and scratch. A blocked image description keeps its input within the bounded budget, which can eventually stop further downloads. Raise the budget, resolve the failed stage or explicitly clear selected failed temporary media; there is no silent eviction of unfinished originals. Other usable text remains available. Restart recovery can clean completed cached assets without repeating inference.

Activity retries move only selected failed/blocked work into an authorized run, preserving automatic retry backoff on other sources. Tool callers can explicitly include waiting work with `queue_control(failed_only=false)`. They do not resume another paused run. Run-level resume is explicit; pause-all remains available. Manual clearing skips active assets, retains durable evidence and marks incomplete work as requiring retrieval. Existing pre-0.7 originals are deliberately left alone; installation never runs a bulk cleanup.

Historical evidence revisions are retained when a refreshed media/page source changes. Their revision/checksum/capture metadata remains available; a refresh does not rewrite old visual evidence as if newly observed.

## Reading and interface

The list is the default; search uses lexical and semantic evidence and ranks distinct bookmarks. Folder filters and saved metric sorting are optional. Item details show saved text, direct context, expandable linked pages, descriptions, transcripts/OCR, engagement snapshots and actionable stage issues. Returning preserves the query, filters, view, scroll position and keyboard focus. Search shows up to 20 top matches with the matching source type, passage and timestamp; opening one targets that evidence even beyond the first page. Counts in browsing refer to the selected folder. Pagination keeps existing rows and defers offscreen rendering.

Dialog headers stay outside the scrolling content; dropdowns remain bounded to the dialog body or Activity viewport. Expanding a Settings section reveals its heading when the section fits.

Failed loads provide a local retry and preserve prior results. Settings save automatically with inline confirmation or rollback; run-limit drafts persist while the panel stays open. Switching list/gallery preserves the visible bookmark. Disconnecting ChatGPT asks for confirmation before removing access.

“Use in ChatGPT” drafts a request without sending it. “Open on X” opens the original. The gallery uses currently cached images and readable text cards after eviction. A React island uses `react-tweet` for rich saved-post cards, with author identity, date, linked text and media. Saved X API data supplies the renderer; no syndication proxy is called. Images load from X when viewed; video streams only on playback, with a fallback when unavailable. Durable text remains readable offline. Only the bookmark’s direct parent and quote appear as context cards.

Original inspection happens through the source/browser when the saved evidence is insufficient. Offline playback and a permanent image gallery are not promised. Search embeddings alone never substantiate claims about unseen pixels.

Library and Activity are sibling pages. List/Gallery stays within Library. Activity owns import, processing, source progress, recovery and paginated history. Settings holds account/model choices, persistent preferences, storage and support. A fixed-size Activity indicator replaces the persistent progress banner; Library refresh is explicit and occupies a reserved toolbar slot.

Activity counts each active bookmark once: active work, actionable issues, automatic retry, waiting, partial/unavailable, or complete, in that priority order. Saved post text remains searchable while media is unfinished. The progress bar uses fully processed bookmarks over the local inventory, never an unknown X-wide total. Source expansion reveals stages and preparation failures. A temporary SQLite reporting table keeps counts and queue pages consistent without parsing every bookmark's raw content; only displayed rows load presentation details.

Import offers Next 100, Next 500 or All available. Its request guardrail is under Limits and disclosed before starting; it is not a spending cap. Continue import grants an additional allowance on the existing run while retaining its cursor, cached page and usage. A fresh import starts separately from media processing. Unfinished legacy imports migrate to import-only and remain paused. Existing processing runs have explicit pause/resume; newly eligible bookmarks can start independently. Pausing remains visible until running stages reach their checkpoints.

Queue order is stable by saved ID. Polling updates visible rows in place, even after they leave the selected filter; Update results deliberately reconciles membership. Query responses are versioned so late responses cannot replace a newer selection. Controls respect connection loss and in-flight actions. Library/Activity navigation and reader return preserve scroll and focus. Menus open outside document flow and close on backdrop/Escape; draft allowances remain in memory for the panel session.

Activity offers targeted retry, website-group recovery and Export diagnostics. The recovery action requests an active desktop agent for a whole website; personal sign-in may still be needed. Settings Support retains diagnostic export. The ZIP contains allowlisted versions, counts, task aliases, error codes, timings, processing preferences, category/error counts, import-dependency gaps, provider waits and run-limit usage, excluding credentials, account/post IDs, URLs, bookmark content and raw logs. It is created locally and never automatically uploaded. The offline `scripts/diagnostics.py` works if the UI cannot open. Storage reports distinguish evidence/index, temporary media and models/runtime.

## Migration, setup and distribution

The migration backs up a pre-0.7 SQLite database before adding run/stage/source/metric tables. Existing evidence and vectors remain. Evidence ownership restricts the reader, lexical/vector retrieval, enrichment and thumbnails to the bookmark and its direct parent/quote sources. Unrelated historical replies and their derived content remain stored but are not exposed. Summaries citing excluded evidence are excluded too. Category/source migration pauses existing runs, reuses legacy saved context and preserves evidence, vectors and original files. Metrics are observed during import, not retimestamped by processing. Updates preserve the library and finish paused; validation uses an isolated library and never starts a bulk import.

The source-only release contains built JavaScript, native Swift source, Python and copy-paste setup/update prompts. Every recipient builds native helpers and downloads Gemma/Parakeet on their Mac. No maintainer signing certificate or Apple Developer account is needed. X credentials remain in Keychain; ChatGPT registration/tokens are private local files excluded from backups and releases. Portable library backups retain saved evidence/indexes, not disposable media or OAuth credentials.

Native processing preflight and the resumable `verify-description.py` are separate requirements. The latter generates an image and frame pair, saves each completed response before proceeding, and reuses saved results on rerun. An account connection alone is not proof that inference works. Fresh-recipient setup, actual MCP host activation and arbitrary real-source quality remain distinct from build checks and isolated rehearsals.

See [verification and limits](KNOWN_ISSUES.md). No unit tests are used. Existing static/build checks and controlled integration rehearsals provide release evidence. Publication and installation are separate actions from implementing or packaging this design.

A `sample` sync imports at most 10 recent bookmarks from one API page, without starting processing. `process=true` is rejected; a combined user request is performed as two explicit operations. It does not scan folders, recurse through references or mark the full inventory complete. A sample is separate from setup/update verification and requires explicit authorization.

## Panel layout

The library and rich reader share a fixed header and content gutters; search remains in Library browsing. Each view scrolls within the remaining host viewport, above the composer clearance. Host dimensions and safe-area changes update the available reading area. Inline and picture-in-picture modes use only the reported bottom inset. The reader commits its React island before the surrounding panel restores focus or scroll position. Media slots use captured dimensions, with bounded video height and stable failure states. Gallery previews use allowlisted captured X image URLs with an optional local-cache fallback; previews do not become durable originals. Browse presentation labels are derived from captured entities without changing source text or embeddings.

Filters live in an anchored top-layer popover, outside the result flow. Its native invoker preserves keyboard order; nested choice menus stay inside the same top layer. The toolbar indicates active filters without adding rows. Empty search submission is inert when browsing; clearing an active or pending query restores browse results and invalidates its late response. Settings exposes the description model directly and shows the active UI version for support.

Folder, sort, account and model controls use a shared Radix Select island with keyboard navigation, typeahead and viewport-bounded menus. Dialog menus portal inside the modal top layer. Account/model controls disable during changes and restore their saved value on failure. Dialog errors scroll into view; busy buttons preserve their width. Shared control states use ink/surface-derived hover and pressed colors, independent of the host secondary surface. Menu selection keeps its checkmark while pointer hover and keyboard focus identify the current target; keyboard focus adds an inset outline. These states change paint only. Disabled/busy controls do not acquire active feedback.

Host theme variables and safe-area insets apply to the panel, dialogs and notification dock. Fullscreen hosts without a reported composer inset reserve 88 pixels; this is a fallback, not a measurement of the host composer. The document itself does not scroll, so content is clipped above that reserved area. Notifications and processing updates stay outside the reading flow. Reading scrollports reserve a constant 48-pixel end inset; the compact error/connection notice sits outside document flow. Routine processing progress appears only in Activity. Dialogs use a viewport-anchored top edge and a separate fixed heading; expanding Advanced or showing feedback grows downward within the safe area. Initial scope/limits are populated before opening. The list keeps its DOM and scroll position during detail navigation; leaving the reader unmounts its player.

Descriptions and captured pages render Markdown with HTML disabled, HTTP(S)-only links routed through the host, and image syntax reduced to alt text. OCR, transcripts and original post text remain literal. Previously saved video descriptions are ordered by asset and numeric time; generated provenance is labelled once per disclosure. Repeated links to the bookmarked post are omitted. These are presentation changes; stored evidence and embeddings are unchanged.
